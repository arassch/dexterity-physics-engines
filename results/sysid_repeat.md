# T26 · How noisy are the system-ID blow-up counts?

Generated by `scripts/sysid_repeat.py` (1024 envs, Newton, num_substeps 8, clamp True (physics_step), ADR max, cube parked, all 64 PhysX references). Each candidate gets 4 blocks of 64 envs per `rollout()` call (same params, same references, different env indices); the same params array is rolled out in 5 separate calls. Scores: Sara's `score_candidate`, unchanged; penalty level fixed at 0.4606 (default candidate, block 1, call 1). Blow-ups = Newton resets over the 3 signals, excluding pairs where PhysX reset (max 192).

## Answer

**The call number dominates every other effect.** In the first `rollout()` call after the env is built, every candidate gets
23–38 blow-ups per 64-env block (means: default 32.0, full fit 34.0, T20 best 28.8, zero point 33.0). Call 2 is
in between (1–9). From call 3 on, counts are almost constant: default **5**, full fit **0** (one block had 1), T20
train best **4–6**, zero point **0–1**. Within a call, blocks differ by about 1 blow-up (mean within-call std
0.7–1.1). Outputs are never bit-identical, not between blocks (0/60) and not between calls (0/64). So, once the
run has settled (calls ≥ 3), the gap between candidates (5 vs 0) is bigger than the block noise (≤ 1). The
call-1 offset (+25–30 for everyone) is far bigger than either. In T19's fit and T20's check, the default (and in
T20 the full fit) were scored **in call 1**, and the penalty level came from that call. Every grid point ran
in later calls. That explains "22 → 0" in T19 and "26 vs 28" in T20: it's the call position, not a lucky grid
minimum. Settled, the full fit does remove blow-ups: 5 → 0 per 64 references. The loss shows the same pattern
(call 1 ≈ 0.34–0.37, later ≈ 0.21–0.24).

## ADR drift (T26b step 1, added 2026-11-17)

Same script and setup, run again with ADR **not** frozen (`--no_freeze_adr --calls 2 --tag drift`, 1,024 envs; full
output `results/sysid_repeat_drift.md`). ADR difficulty (`DifficultyScheduler.current_adr_difficulties`) and the
gravity applied in Newton (`model.gravity`, per world), read at the start of every signal after the reset:

| call | signal | ADR mean | ADR min–max | gravity z |
|---|---|---|---|---|
| 1 | a | 8.00 | 8–8 | −7.85 |
| 1 | b | 6.84 | 5–7 | −6.71 |
| 1 | c | 5.71 | 3–6 | −5.60 |
| 2 | a | 4.49 | 2–5 | −4.41 |
| 2 | b | 3.49 | 1–4 | −3.42 |
| 2 | c | 2.48 | 0–3 | −2.44 |

The difficulty starts at 10 (Play config) and loses 1 on every reset without success: 2 resets before the first signal
(env construction + the harness's first `u.reset()`), then 1 per signal reset, plus 1 per mid-signal reset in that
env. Gravity follows the *mean* difficulty. Blow-ups per block: call 1 default 34/26/24/25, full fit 31/41/35/28;
call 2 default 6/6/4/4, full fit 5/5/4/6 (the same pattern as T26). The PhysX reference `t19_ref_physx.npz` drifted
the same way (its log: gravity −5.79 after signal c). With ADR frozen (`--freeze_adr`, now the default) the difficulty
stays at 10 and gravity at −9.81 in every signal and every call: see `results/sysid_repeat_adrmax.md`.
